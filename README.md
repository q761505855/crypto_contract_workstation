## 手机和平板访问

桌面以图表为主体，右侧下单，底部通过“持仓／成交记录／复盘统计／账户流水”标签切换。账户详情、仓位详情、止盈止损、减仓和平仓按需打开。账户摘要、下单、持仓与复盘、回放控制和底部状态都可通过标题箭头展开／收起；收起后原位保留展开条，右侧下单区保留展开窄轨。顶部“工作区”也可统一切换这些状态或恢复默认布局；“专注看图”临时收起附加面板，退出后恢复原布局。

手机（宽度小于768px，或宽度小于1024px且高度不超过520px的横屏）保留固定底部“看图／下单／持仓／更多”，下单及持仓通过抽屉打开。再次点击当前底栏“下单”或“持仓”按钮即可收起，点击“看图”、遮罩、标题箭头或按Escape也可收起抽屉；编辑弹窗有独立关闭入口、焦点循环和返回。纵横屏切换沿用同一个图表与下单草稿。手机默认收起主图指标信息与绘图侧栏，保留主图价格信息及副图指标信息，可以随时展开；日期、数字输入和抽屉会根据可见视口避让软键盘。

顶部“图表尺寸”可调整整体图表与各指标副图高度，也可拖动图表底边。桌面与手机分别记住整体高度，“自动适配”恢复填充当前可用空间；副图高度与指标配置一起存档。空间不足时只临时压缩副图显示，保留约180px的主图空间，不会把压缩值覆盖到存档。手机手动增高图表后，顶部与底部导航仍可直接操作。布局及高度偏好支持本地恢复、JSON备份和GitHub应用配置同步；恢复配置后按界面提示刷新。详见[工作区使用说明](docs/workspace-experience.md)。

周期下拉框包含全部 15 个周期，列表右侧星标用于固定或取消固定快捷周期；默认固定 5m、15m、1h、4h，选择会保存到当前浏览器，并进入应用配置／全部数据备份及 GitHub“应用配置”同步。快捷栏仅显示固定的周期，手机窄屏时另起一行；固定较多时只在快捷栏内横向拖动，页面不会跟随左右移动。

价格轴支持单指上下拖动缩放和双指捏合缩放，调整后进入手动价格范围；双击价格轴或点击“自动”恢复自适应。图表内横向滑动浏览历史，双指捏合调整时间尺度，纵向滑动可滚动页面；点击或长按图表显示十字光标后，可拖动查看行情。

移动端回归使用 Chromium 触摸模拟，覆盖 320px、390px、768px、横竖屏切换、回放与模拟下单，以及价格轴拖动、捏合、手势取消和页面滚动。实际 iOS Safari 和 Android 浏览器仍需真机验证。

## 图表指标

在图表“设置 → 蜡烛图类型”选择“平均 K 线（Heikin Ashi）”可查看平滑趋势。蜡烛按 HA 公式计算，提示框、指标、最新价和模拟交易仍使用真实行情，图表会显示提示。首根从已加载历史的开收均值起算，向左加载更多历史后会重新递推。类型选择刷新可恢复，并包含在应用配置／全部数据 JSON 和 GitHub“应用配置”同步中；旧存档缺少类型时保留本地设置，恢复后按提示刷新。

MA、EMA、BOLL、MACD、RSI 等现有指标使用 `klinecharts` 内置实现，指标菜单和参数设置由 `@klinecharts/pro` 提供；行情接入、回放隔离和指标配置保存由本项目实现。

“指标 → 主图指标 → KC(肯特纳通道)”显示上、中、下三轨。参数依次为 EMA 周期、ATR 倍数、ATR 周期，默认 `20、1.5、20`，倍数支持小数。中轨为收盘价 EMA，上下轨为中轨加减倍数乘 ATR；EMA 用完整窗口 SMA 起始，ATR 首根取 high-low、之后计入相对前收盘价的跳空，以完整窗口 SMA 起始并按 Wilder 平滑。等待两个周期都预热完成才绘制；支持分别修改三轨颜色。

“指标 → 副图指标 → TTM Squeeze(挤压指标)”组合布林带、同一现代肯特纳通道和回归动量：

- 参数依次为共同周期、布林带标准差倍数、KC ATR 倍数，默认 `20、2、1.5`；周期应用于 BB、KC 的 EMA/ATR 和动量计算。
- BB 使用收盘价 SMA 与总体标准差。BB 上轨严格低于 KC 上轨且下轨严格高于 KC 下轨时，零轴显示红点（挤压中）；其他情况显示绿点（未挤压）。红转绿表示挤压解除，持续绿点不代表新的释放信号。通道预热完成才显示圆点。
- 动量基础值为 `close - ((窗口最高价 + 窗口最低价) / 2 + SMA(close)) / 2`，再对同周期基础值做线性回归，取拟合线末端值。默认第 39 根 K 线才开始显示动量柱；此前悬浮值为 `--`。
- 正柱升高／回落分别为青／蓝色，负柱远离／靠近零轴分别为红／黄色；正柱持平按青色、负柱持平按黄色显示。设置窗口可分别修改四色柱和两种状态点的颜色，悬浮提示显示动量和挤压状态。

TTM 的挤压与回归动量思路参考 [StockCharts 指标说明](https://chartschool.stockcharts.com/table-of-contents/technical-indicators-and-overlays/technical-indicators/ttm-squeeze)，本项目明确采用上述现代 KC 公式；使用原始肯特纳公式、不同 EMA/ATR 起始或平滑方式的平台可能出现不同信号，不承诺跨平台逐点一致。挤压本身不判断方向，动量减弱不等于趋势反转，也不保证释放后会持续突破。

KC 和 TTM 均为自定义指标，不增加依赖、不自动加入默认组合。实时与回放计算仅使用当前及之前提供的 K 线；未完成实时 K 线会更新。选择、参数、可见性、颜色样式和副图高度都沿用现有本地保存、应用配置／全部数据 JSON 导出导入和 GitHub“应用配置”上传恢复。旧存档不自动新增指标，缺少指标配置时保留本地值，显式空列表表示清空；新指标非法参数会在恢复写入前拒绝。导入或云端恢复后按界面提示刷新生效。

“指标 → 副图指标”提供三个独立的 **TTM Wave A（短期波）／B（中期波）／C（长期波）**，可分别勾选、移除、隐藏和调整副图高度。参数依次为快线、慢线一、慢线二周期，默认 A 为 `8、34、55`，B 为 `8、89、144`，C 为 `8、233、377`；必须是正整数且依次递增。设置窗口可修改周期和两组波形颜色，各指标互不影响。

采用 [UDAY_C_Santhakumar 公开 ABC 版本](https://www.tradingview.com/script/nYOzTA1Y-UCS-TTM-Wave-A-B-C/) 的数学口径独立实现：设 `D(p) = EMA(close, 快线) - EMA(close, p)`，`H(p) = D(p) - EMA(D(p), p)`。A/B 的波形一为 `H(慢线二)`、波形二为 `H(慢线一)`；C 的波形一为未经信号平滑相减的 `D(慢线二)`、波形二为 `H(慢线一)`。两组柱状波叠加并显示零轴：每组按自身数值正负着色，上方默认深／浅绿色，下方默认红／橙红色，零值沿用上方颜色。设置窗口可分别调整“波形一／二零线上方／下方颜色”。旧存档的单色保留为上方颜色，下方使用新的默认色；新颜色完整参与本地、JSON 和 GitHub 配置存档。短中长期均指当前图表周期的 EMA 长度，不额外读取更高周期。

Wave 的 EMA 从首根收盘价起算，信号 EMA 从首个差值起算，首根值为 0；只用当前及此前 K 线。尤其 B/C 会受加载历史长度和初始化方式影响；该公开 ABC 版本不承诺与 thinkorswim 闭源 A/C 合并版本逐点一致。三个指标的选择、参数、可见性、颜色和副图高度均进入现有本地、JSON 配置／完整存档和 GitHub“应用配置”往返；旧存档不自动添加指标，恢复后刷新生效。

ABC 之间只保留轻微色调差异，主要以绿色系／红色系区分零线上下。每个副图的波形一使用较深的宽柱，波形二使用较浅的半宽柱，避免 C 波两组数值接近时完全遮挡。读取本地配置或恢复旧存档时，已发布的旧默认色自动升级到当前配色，其他自定义颜色保留；迁移参与现有 JSON、完整存档和 GitHub 配置流程，不新增设置字段。

在“指标 → 主图指标”勾选 `Supertrend(超级趋势)`，可与 MA 等指标叠加。点击图表指标标题旁的设置图标，可修改 ATR 周期和倍数，默认分别为 10 和 3，倍数支持小数；选中状态和参数随现有指标配置保存、备份及恢复。

Supertrend 是本项目通过 KLineCharts 自定义指标接口实现的扩展，不增加额外依赖。计算采用 [TradingView 公开标准公式](https://www.tradingview.com/support/solutions/43000634738-supertrend/)：以最高价和最低价的中点构建 ATR 轨道，ATR 使用 Wilder 平滑（首个周期简单平均，再递推），收盘价穿越轨道后切换方向。上涨为绿线，下跌为红线，方向切换处断开；不足一个 ATR 周期时不显示数值。回放计算仅使用当前及之前已提供的 K 线，未完成的实时 K 线会随价格更新。尚未与币安平台做逐点数值校准，历史加载范围、ATR 算法或初始值不同都可能造成差异。

“指标 → 主图指标 → Pivots(标准枢轴点)”提供所附 Pine v6 `Pivot points standard` 的移植版本：

- 支持 Traditional、Fibonacci、Woodie、Classic、DM、Camarilla 六种公式，默认 Traditional；
- 枢轴周期支持自动、日、周、月、季度、年及 2/3/5/10 年；自动规则按所附脚本：15 分钟及以下用日，其他日内周期用周，日线用月，周线/月线用年；
- 默认保留 15 组历史，支持 1–200 组，并遵守最多 500 条水平线的显示上限；
- 支持标签、价格、左右位置、线宽，以及 P、R1–R5、S1–S5 各级线的独立显示开关；颜色简化为 P、R、S 三组，同组共用颜色，当前公式不支持的级别会禁用；
- 勾选“当前周期显示上期线”后，将紧邻上一枢轴周期当时的水平线叠加到当前周期，以虚线和“上期”标签区分；上期 P、R、S 也可单独设色，默认关闭。仅当前一段叠加，不在所有历史周期重复延伸；上期线同样遵守各级显示开关，计入 500 条绘线限制；
- 使用上一完整枢轴周期的 OHLC；Woodie 还使用当前周期的开盘价。各周期水平线独立绘制，日历边界按币安 UTC 计算，显示时区不改变计算边界；
- 默认“使用日线基准数据”从同一行情源读取日/周/月 K 线，季度和多年周期由月 K 线聚合；关闭时仅聚合已加载的图表 K 线，不完整或有缺口的前一周期不会生成水平线；
- 当前周期最后一根 K 线确认完成后，可预先绘制下一组水平线；Woodie 等待下一周期开盘，避免使用未知的开盘价；
- 状态及全部参数随现有指标配置保存、备份和恢复。

上期线是“上一枢轴周期当时显示的线”，例如周枢轴在本周叠加上周那组线，而不是把本周计算结果重复绘制；Woodie 的上期线使用上期开盘价。需要再前一个完整周期的数据，日线基准模式会多取一组历史，即使历史组数为 1 也能叠加；关闭日线基准时仅使用图表已加载数据，有缺口时不补画。旧版每线独立颜色迁移为 P、R1、S1 对应的分组颜色；原始默认橙色迁移为当前 P 橙、R 红、S 绿，各级开关保留。旧存档缺少上期线设置时保留目标浏览器已有的开关与上期颜色；没有已有设置时默认关闭。颜色与开关完整参与本地、JSON 配置／完整存档和 GitHub“应用配置”往返，恢复后刷新生效。

高周期读取沿用缓存、回放截止时间和行情请求保护，不切换主图周期；同一来源周期内复用请求，失败后不随每次行情更新反复重试，刷新数据或跳转时重新读取。仍受单次历史读取最多 499 根来源 K 线及已上市历史长度限制。数据不足时，指标标题旁提示所需历史；可在数据管理准备相关日期范围后刷新。这里只移植该指标的计算和绘图，不执行 Pine 脚本；使用币安普通 K 线收盘价，没有股票扩展交易时段或期货结算价数据源，因此跨平台数值可能因数据源不同而不同。

## 下载历史数据

1. 启动应用并点击右上角“数据管理”；
2. 选择交易对；图表周期不影响下载，统一保存 1m 基础数据；
3. 设置开始时间和结束时间，查看实际缓存范围；默认选择上一个完整 UTC 月，短范围扩展到涉及的自然月；
4. 点击“下载历史数据”，统一准备普通价格分钟 K 线；
5. 全部所选月份校验并缓存到 IndexedDB，后台自动上传默认云端。当前月份只准备到最后已收盘分钟，上市前和未来时间不计缺口；
6. 下载可取消，已完成月份保留；云端待上传状态持续显示在页脚，点击进入数据管理后使用“重试待上传”，不必重新下载。

日期跳转自动准备目标月份，无需先到数据管理。读取顺序为本地分钟缓存、GitHub 月分片、币安官方月归档、官方日归档；仅近 30 个 UTC 自然日的归档缺口允许受请求保护限制的 REST 补齐，并自动合并回原来的 Git 月分片。归档网络错误、损坏或更早日期缺失会明确提示，不转成大量历史 REST 请求。其他周期由连续分钟数据聚合，缺口不能伪造成完整 K 线。

创建和恢复回放会话复用同一套按月准备流程，只检查普通成交价格，不再按 499 根拆分重复补数。创建时只准备截至点击时已收盘的周期，界面显示当前月份及来源进度。当天未结束的日归档不发起探测；已经返回 404 的归档短期复用缺失结果，避免重复请求。

普通浏览、翻页和指标后台读取每次最多补两个涉及月份，较早的已缓存数据仍可读取；需要长周期指标的完整多年基准时，在数据管理明确准备相应范围。用户明确选择的下载和回放范围不受图表 499 根窗口限制，不会静默缩短结束时间。

远程行情采用保守请求保护：REST 请求最少间隔 2 秒，同一浏览器的同源页面共用每分钟最多 10 次、每小时最多 100 次的额度，每页最多 499 根 K 线，超额直接停止本次请求，不自动重试。刷新页面、更换接口地址不会清空额度。多页面不能协调或保护记录不能读写时，不发送远程请求。

收到 HTTP 429、418、403、币安限流错误码或出口 IP 权重达到保守阈值（100）时，会持久暂停新增 REST 请求，至少冷却 30 分钟；服务端指定更长时间时，以更长时间并增加一分钟缓冲为准。到期不会自动恢复，需要在“数据管理 → 行情请求保护”点击“手动恢复远程请求”。恢复操作本身不会发起数据请求。暂停期间仍可读取本地、GitHub 和官方归档，但不能通过 REST 补缺。其他浏览器、不同站点或共享出口 IP 的其他程序不受本应用控制。

## 开始历史回放

1. 在图表或“数据管理”中选择交易对和周期；
2. 可输入“图表时间”直接跳转，或拖动图表确定回放起点；
3. 创建回放时自动使用图表视口最右侧 K 线作为起点；结束时间可选，留空时回放到最新已完成 K 线；
4. 点击“创建回放”，系统会检查缓存并自动补齐普通 K 线；
5. 创建时可设置初始资金、杠杆、手续费率、滑点率和强平参数；
6. 在右侧面板按保证金金额或仓位数量模拟开多、开空；多仓和空仓可以同时存在，同方向加仓合并，分别减仓或平仓；
7. 在各自的仓位卡片设置止盈和止损，或拖动对应仓位的图表价格线；触发时仅关闭该仓位。同向加仓、部分减仓保留该仓位的止盈止损，完全平仓后清除；系统从设置后的下一根 K 线开始依次检查强平、止损和止盈；
8. 使用上一根、下一根、播放速度、跳转结束和重置控制进度；
9. 刷新页面后，活动会话、账户、持仓、成交和回放进度会自动恢复。

活动回放会话只向图表和指标提供当前回放时间及以前的 K 线。产生交易后禁止回退；重置会话会清空该会话的模拟账户、持仓和交易记录。预估强平采用训练用近似模型，不代表币安实际强平结果。

双向持仓分别占用逐仓保证金、计算浮盈亏和强平价，账户汇总两边的数值。同一根 K 线会分别处理两边的触发，不会在一边退出后跳过另一边。持仓及绑定的止盈止损随本地自动保存、会话／全部数据 JSON 和 GitHub“会话与交易”上传恢复；旧单仓存档自动迁移，恢复导入后按界面提示刷新。详见 [模拟双向持仓](docs/simulation-positions.md)。

创建会话先准备起点所在 UTC 月及下个月；恢复会话只准备到当前进度的下个月，不一次下载到会话终点。例如 1 月创建仅准备 1、2 月，回放进入 2 月再补 3 月。完整会话终点和总步数保留，缓存边界不代表回放完成。数据继续优先读取本地／Git 月归档，再读币安归档，最近缺口才用 API；已有缓存不会重复下载。恢复较晚进度时会读取起点至当前进度的必要历史，保留回退和重置能力。

已经准备好的下一根、播放和模拟开平仓使用内存行情，不逐根请求接口。跨月按需补一个月，失败时停在原进度，可重试；“跳转结束”是主动处理完整会话，会逐月补数据并逐根处理交易。提前缓存的行情仍受当前已揭示时间限制。强平、止盈、止损与持仓浮盈亏均以同一份普通价格计算，不再依赖标记价格。上述预加载策略是运行逻辑，不新增用户配置或会话存档字段，旧 JSON／GitHub 会话可继续恢复。

回放过程中可以自由切换图表周期，当前进度、持仓和交易记录会保留。回放控制栏的“步进”周期沿用创建会话时的周期，切换图表周期不会改变模拟交易的推进和结算。图表优先读取本地数据，较大周期优先由已知的小周期数据合成，不会显示未来价格；不能从大周期还原尚未下载的小周期走势。图表缺口按已揭示范围合并补齐，月份缓存和重叠请求继续复用；会话推进按上述月份窗口补数据。所有 API 请求仍受全局额度、冷却和跨页面保护约束，不会绕过限流。

切周期会恢复当前视口右侧对应的时间位置，切回小周期保留原来的具体时间。“定位最新”在实时模式回到最新行情，在历史会话中只回到当前已揭示的最新 K 线，不推进回放。日、周、月的当前未完成 K 线仅由已揭示分钟合成；详见 [多周期观察与图表定位](docs/chart-navigation.md)。

## 查看实时行情

1. 点击顶部“实时行情”；
2. 图表先从分钟缓存、GitHub 和官方归档加载最近历史，仅近期未归档部分使用 REST；
3. 可在页面底部输入“图表时间”，直接加载并跳转到对应历史位置；
4. 页面随后连接币安 USDⓈ-M 公共 WebSocket，持续更新当前普通 K 线和最新成交价格；
5. 已完成 K 线自动写入 IndexedDB；
6. 建立连接和重连均不触发 REST 自动补缺，缺失数据先保留；自动重连最多三次，等待时间逐次增加，持续不稳定时停止并提示手动重试。新增 WebSocket 连接同样共享保护额度，最少间隔 10 秒，每分钟最多四次、每小时最多 30 次。

实时模式不显示模拟交易面板或任何下单按钮。

## 备份与 GitHub 同步

默认连接可供多个个人应用共用的 [云端存储仓库](https://github.com/q761505855/personal-cloud-storage)，当前项目只读写 `projects/crypto-contract-workstation/`。配置位于 `config/`，行情位于 `data/market-history/`；其他项目和顶层注册表不受影响。详见 [通用云端存储约定](docs/cloud-storage.md)。

指标、收藏列表、固定周期列表、当前产品和行情地址均纳入配置存档。导入备份或云端拉取后，刷新页面以应用恢复的配置。旧存档缺少固定周期字段时保留本地设置，显式空列表则恢复为不固定任何周期。

后续配置修改必须遵守 [配置持久化与存档约定](docs/configuration-archiving.md)，项目级要求见 [AGENTS.md](AGENTS.md)。

1. 打开右上角“数据管理”，在“本地备份”中导出配置、当前行情、单个会话或全部数据；
2. 导入 JSON 备份时，应用会先完整校验格式、时间顺序、重复记录和数值，再写入 IndexedDB；
3. 默认仓库无需填写信息；历史自动上传使用内置构建授权，配置仍通过“应用配置”手动比较、上传和恢复；
4. 也可填入其他已有仓库及 Token，继续使用旧的仓库根目录存档；修改默认共享仓库的分支时仍保持当前项目目录隔离；
5. 拉取会先校验 `manifest.json`、文件大小和 SHA-256，全部通过后才合并到本地；
6. 默认授权从本机 `.env.local` 或 Pages 构建 Secret 接入；手动输入的 Token 只保留在页面内存，“清除手动 Token”会清空输入，默认构建连接继续可用。凭据不进入配置备份、云端数据或日志。

IndexedDB 是运行时缓存，GitHub 同时承担按需历史读取和存档。新行情按项目内相对路径
`data/market-history/{symbol}/1m/{year}/{month}.json.gz` 保存，兼容旧 `market-data/` 分片和多周期 JSON 存档。
自动历史上传先合并云端已有普通价格日期，再原子提交分片及清单，冲突时保留本地并提示重试；配置操作沿用现有差异和冲突处理。

新行情分片、JSON 备份和模拟账户快照均不写标记价格。旧存档的 `markCandles` 仍校验但不恢复；旧持仓优先保留 `lastPrice`，仅在缺失时将旧 `markPrice` 迁移为当前价格字段，恢复活动会话后按当前普通 K 线重新估值，不重放已完成成交。本地旧标记价格缓存不参与新计算或导出。指标、收藏、固定周期、当前产品和行情地址的本地、JSON、GitHub 配置往返保持完整。
