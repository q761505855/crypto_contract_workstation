# 历史行情与通用云端存储统一需求

更新日期：2026-11-05。本文合并历史行情模拟改造、分钟数据基准、归档优先和 GitHub 通用云端存储要求，作为实现与验收依据。功能与回归已完成，代码保存在本地功能分支，尚未推送或发布。

## 统一需求概览

### 1. 使用体验

用户跳转到历史日期时，应用自动查找和准备所需数据，不必先到数据管理按周期下载。已经获取的历史数据保存到本机，并自动保存到云端；以后优先复用已有缓存和归档，不必手工下载、解压和导入文件。切换周期时继续使用同一份基础数据。

### 2. 历史数据准备

- 固定下载 `1m` 数据，其他支持周期统一由分钟数据计算，不跟随图表周期重复下载。
- 普通成交价格和标记价格明确区分，分别保存和聚合，不能相互替代。
- 单次历史下载至少以一个月为准备单位；用户明确选择起止时间时，必须完整处理整个范围并缓存。
- 当前月份或上市不足一个月时，以实际可用历史为准，不能要求未来或上市前数据。
- 支持跨月、取消、失败重试、复用已完成月份；不能只下载一页，或将部分成功显示为整体完成。
- 图表跳转自动准备目标所需数据；普通浏览按需加载，不能因图表内部预取窗口意外下载多年分钟数据。
- 回放不能静默缩短用户选择的结束时间；提前缓存的未来分钟不得泄露到当前图表或交易模拟。

### 3. 数据源顺序

```text
本地有效缓存
  → GitHub 当前项目历史归档
  → 币安官方月归档
  → 币安官方日归档
  → 仅限近期尚未归档部分使用 API
```

只要可取得归档，就优先读取归档。旧历史遇到网络错误、缺文件或校验错误时，应明确报告原因，不能转为大量 API 请求。保留现有请求额度、冷却和跨页面保护。

实现参考 `D:/MyWorkSpace/web_trade_system` 的月度 ZIP 下载、`.CHECKSUM` 验证、预期 CSV 读取，以及分钟聚合验证逻辑；参考项目不做修改。

### 4. 默认云端连接与历史自动同步

- 默认使用公共仓库 `q761505855/personal-cloud-storage`，分支 `main`。
- 仓库地址、项目目录和凭据接入前端构建，打开即可使用，不必每次填表或手动连接；按用户选择保持简单部署，不增加后端或 GitHub Actions 下载流程。
- 历史数据下载、校验和缓存成功后自动上传；之后只按需读取所需交易对和月份，不整批恢复配置、会话和交易。
- 重复内容不重复上传；局部上传保留同月其他日期、另一类价格及其他月份，不覆盖更完整的云端内容。
- 上传失败时保留本地，显示“已缓存，待上传”，支持重试；云端失败不阻止使用已经缓存的数据。
- 沿用现有大小、校验和、差异和冲突检查，不静默强制覆盖。
- 凭据通过本地 `.env.local` 接入构建，不进入业务存档或日志；前端构建产物会包含内置凭据，这是用户已经选择的方式。

### 5. 通用仓库与项目隔离

```text
personal-cloud-storage/
  storage.json                        # 通用项目注册表
  projects/
    crypto-contract-workstation/
      manifest.json                   # 当前项目独立清单
      config/                         # 当前项目用户配置
      data/
        market-history/               # 当前项目历史行情
    <其他项目>/
      manifest.json
      config/
      data/
```

仓库面向多个个人应用，不绑定交易工作站。各项目使用稳定项目 ID，独立维护配置、业务数据类型和清单；新增项目扩展注册表。当前项目只能更新自身命名空间，不得覆盖其他项目文件、清单或注册信息。项目清单内的路径相对该项目根目录。

### 6. 用户配置与兼容

指标选择、参数和样式、收藏、固定周期、当前产品、行情地址等已有设置，继续完整覆盖本地持久化、JSON 配置导出、完整导出和 GitHub 上传／恢复。新设置必须遵守 `docs/configuration-archiving.md`，不能只做界面或 localStorage。

历史行情属于数据目录，用户设置属于配置目录，Token 和设备请求保护状态不进入配置存档。兼容旧 JSON、云端清单、多周期缓存和回放会话；缺字段不覆盖对应本地设置，显式空列表、`false` 和 `0` 不当作缺失。恢复配置后沿用明确刷新提示，防止旧组件状态写回。

目前已经确定“历史下载后自动上传”和“默认仓库免配置”。配置是否每次修改后自动上传、是否启动即自动覆盖本地配置，尚未约定；不将这些行为当作已确认要求。现有配置比较、上传、拉取和冲突处理入口保留，并接入默认仓库。

### 7. 实施默认建议与当前状态

以下细节由实现方案提出，尚未由用户逐项确定：按 UTC 自然月缓存，短范围扩展到所涉及的整月；近期 API 仅限近 30 个 UTC 自然日内、归档无法提供的缺口；默认一键准备普通价格和标记价格。界面必须提前显示实际缓存范围。该近期窗口覆盖真实发现的上月底归档缺日，仍禁止将更早历史批量转为 REST。

已完成：创建公共仓库、通用注册表和项目隔离目录，初始化空清单，验证公共读取，保存本地构建信息并设置 Git 忽略，将存储约定写入项目文档和 `AGENTS.md`。

已接入：分钟聚合、归档下载、完整范围缓存、历史跳转和回放、默认云端连接、历史自动上传和按需读取、配置同步默认目标，以及 Pages 构建凭据。2025 年 9 月 BTCUSDT 的普通价格、标记价格各 43,200 根已实际上传并通过云端拉取校验；未替用户构造或上传配置。

单元测试覆盖配置完整往返、旧存档兼容、缺口与时间边界；浏览器最终回归结果另记在实施计划中。

## 用户要求与目的

历史图表跳到 2025 年 9 月时应能直接获取数据，无需先到数据管理按周期下载。统一下载 1 分钟数据，其他周期由它计算；单次至少处理一个月，明确选择起止范围时必须完整下载并缓存。下载后自动上传现有 GitHub 数据仓库，之后优先读取仓库中的归档。用户进一步要求参考 `D:/MyWorkSpace/web_trade_system`：凡有归档都优先读归档，只有近期数据才走 API。

参考实现为 `trade_server/src/download_history.py`：按月获取币安 USD-M futures ZIP 和 `.CHECKSUM`，先验证 SHA-256，只读预期 CSV，成功后保存；`trade_server/src/verify_multi_timeframe.py` 提供分钟聚合的独立验证和未来数据检查。参考项目仅供阅读，不修改。

## 现状与约束

- 当前 `MarketDataService` 按交易对、数据种类和周期直接请求 REST 并保存，分钟缓存不会自然供其他周期复用。
- 数据管理默认七天，下载使用图表周期；图表跳转只是查询目标附近最多 499 根。
- REST 每页 499 根，应用有每分钟 10 次、每小时 100 次请求保护，不能以放松保护解决整月下载。
- 回放创建使用实际返回的最后一根作为结束时间，存在只拿到前半段却缩短用户选择范围的风险。
- GitHub 已有按交易对、周期、年月的 gzip 分片、manifest、SHA-256 校验和冲突流程；目前只有手动整批恢复。
- 产品为静态网页，沿用 React、TypeScript、IndexedDB 和现有 GitHub Contents API，不增加后端。
- 用户要求前端内置连接信息和写入凭据，取消每次在界面填写的流程。本机 `.env.local` 保存构建信息，按用户选择将凭据用于前端构建；Token 不提交 Git、不进入用户配置备份或日志。请求保护额度、冷却和跨页面锁不进入配置存档。
- 已创建通用公共仓库 `q761505855/personal-cloud-storage`，分支 `main`；当前项目使用 `projects/crypto-contract-workstation/`。仓库还将服务其他项目，必须遵守 `docs/cloud-storage.md` 中的命名空间与注册表规则。

## 方案取舍

1. **浏览器下载归档并自动上传 GitHub（采用）**：可复用参考项目的数据源和现有同步，不要求用户设置后台任务；浏览器自动完成校验、解压和缓存。用户已选择“下载完成后自动上传”。
2. GitHub Actions 预生成归档：可移走浏览器下载工作，但需要额外工作流、权限和任务管理，目前没有必要。
3. 统一分钟 REST 分页：改动较少，但整月双类数据受现有保护限制，违背体验诉求，排除。

## 数据读取与归档规则

读取顺序为：已校验的本地分钟缓存 → 已连接 GitHub 中的分钟月分片 → 币安官方月归档 → 官方日归档 → 近期未归档部分的 REST。

- 月归档地址沿用参考实现，普通价格为 `data/futures/um/monthly/klines/{symbol}/1m/{symbol}-1m-YYYY-MM.zip`；标记价格对应 `markPriceKlines`。日归档使用 `daily` 和 `YYYY-MM-DD`。
- 对所有已结束月份先尝试月归档；月文件尚未发布或不存在时，逐日读取已结束日期的日归档。当前月份也对已结束日期优先查日归档。
- 只有当前 UTC 日及前一个 UTC 日、且对应日归档确实尚不可用的部分允许 REST（作者提出的近期边界）。网络错误、超时、限流、校验失败不等同于归档不存在；旧日期缺归档时报告缺失，不回退大量 REST。
- ZIP 和 `.CHECKSUM` 必须配对验证；只接受预期文件名、结构和数据种类，不按 ZIP 内任意路径解压。CSV 处理表头、分钟对齐、顺序、重复、合法数值和交易对信息，整份验证通过才写入。
- 一个分片失败不得留下该分片的部分内容；其他已完整校验并保存的月份保留，允许重试复用。异常清楚区分数据源、日期及失败原因。
- 重叠和并发请求共享下载，同一有效归档不重复下载或解压；缺失和失败只在本次任务内去重，显式重试可重新获取，不能永久缓存 404。

## 范围、下载和图表行为

- 数据管理下载脱离图表周期，固定为 1m；默认范围为一个月。默认一键准备普通 K 线和标记价格，界面展示两类的状态与缓存覆盖范围。
- 明确范围按涉及的 UTC 自然月展开，例如 9 月 12–14 日实际缓存整个 9 月；跨月至少覆盖所有涉及月份。界面在下载前展示实际缓存范围，输入仍按用户本地时区显示，并标明归档按 UTC 分月。
- 当前月份只下载到已经结束的分钟，上市前和未来时间不计为缺口。因当前月或上市时间而不足整月时明确显示实际可用范围。
- 范围遍历不受图表 499 根限制，逐月处理直到全部完成、取消或报告失败。下载与上传分开报告；不能将部分成功显示为整体完成。
- 下载结束检查整个可用请求范围的连续性，包含尾部；不得用最后返回时间静默缩短用户选择范围。回放准备同样执行此规则。
- 图表跳转自动准备目标日期所需月份，显示进度；无需用户先打开数据管理。图表内部预取窗口不能被误解为用户要求下载多年分钟数据：普通加载、翻页按月逐步补充，明确选择的起止范围则必须完整准备。
- 取消中止网络和后续处理；已完整保存的月份保留，未完成月份可重试。

## 分钟聚合与回放

- 普通价格与标记价格分别保存并聚合，不能相互替代。后续下载和新上传的行情以 1m 为基准，不为显示周期重复请求和存储相同历史数据。
- 聚合沿用现有 UTC 对齐函数：开盘 first、最高 max、最低 min、收盘 last，成交量、成交额和笔数相加；字符串金额使用项目已有 decimal.js，图表接口再转为数值。
- 周线按 UTC 周一，月线按自然月；跨月、闰月和周边界均须正确。
- 完整 K 线要求所需分钟连续；有缺口不能伪造完整 K 线。
- 回放可预先缓存未来月份，但展示和模拟撮合只读取当前可见边界之前的分钟。未完成的大周期柱只由已揭示分钟合成，缓存的未来收盘价不得泄露。
- 兼容旧存档中的其他周期数据和已有回放会话。旧大周期可以继续用于原有数据读取，但不能反推出分钟或标记为已具备分钟覆盖；新取得的完整分钟数据作为统一基准。

## GitHub 自动上传与按需读取

- 运行时默认使用前端构建中内置的仓库信息和凭据，自动连接当前项目命名空间；关闭数据管理、刷新页面无需重新填写。用户不再需要先手动配置仓库。原有手动连接功能如保留，不能改变默认目标的项目隔离规则。
- 云端读写必须限制在当前项目命名空间内；项目清单只管理当前项目文件，不能替换顶层 `storage.json` 或影响其他项目。
- 读取仅获取当前所需交易对与月份的分片，不整批恢复配置、会话和交易；校验 manifest、大小、SHA-256、分片结构和行情数据后写入 IndexedDB。
- 下载并校验完成的月份自动上传；只处理本次相关行情分片，使用 `projects/crypto-contract-workstation/data/market-history/{symbol}/1m/{year}/{month}.json.gz`，沿用现有项目清单格式。清单位于本项目根目录，内部路径相对该根目录。兼容旧 `market-data/` 相对路径；无需用户手工解压。
- 上传前合并远端同月已有的其他日期和另一类价格，保留未涉及的远端月份及所有其他类别清单项，避免局部缓存覆盖完整远端。
- 内容无变化时跳过写入；使用远端 SHA 和 manifest SHA 处理竞争更新，冲突沿用已有处理方式。后台自动上传默认遇到冲突停止并提示，不能默默强制覆盖。
- 本地下载成功但上传失败时保留本地，明确显示“已缓存，待上传”，提供重试；未连接时显示“已缓存，连接仓库后可上传”。自动上传不阻塞图表使用已缓存数据。
- GitHub 读取支持超过 1 MiB 的分片，以适配整月双类分钟数据；不能只依赖小文件 base64 内容。沿用鉴权 API，避免把 Token 拼进 URL。

## 验证与交付

必须运行 `npm run check` 和对应 Playwright 场景，覆盖：

1. 2025 年 9 月跳转冷缓存时读月归档，归档可用情况下历史段 REST 调用为零；第二次读取走缓存。
2. 一个完整月、跨月、短范围展开为整月、上市边界、当前月份；无 499 根截断，尾部缺失不能报完成。
3. 月归档不存在用日归档；近期缺日归档才用 REST；旧月份 404、网络失败、校验错误不触发旧数据 API 风暴。
4. ZIP/CSV 异常、校验失败不写入；取消、部分月份成功、重试、并发复用。
5. 从 1m 聚合所有支持周期，对照独立预期检查 OHLCV、笔数、周月边界、缺口与回放未来数据隔离。
6. GitHub 自动上传、按需读回、超过 1 MiB、无变化跳过、只上传某月仍保留远端其他月份、并发冲突和上传失败重试。
7. 本地/JSON/云端配置完整往返，旧字段缺失与非法配置；Token 与请求保护状态不进入存档；构建变量默认连接和项目路径隔离正确。
8. 旧多周期存档和已有会话仍可恢复；更新 README 与配置清单，明确需要 Token、实际下载范围和状态含义。
9. 添加另一个项目目录和注册项作为隔离样本；本项目配置与历史数据上传不得修改它们或丢失其注册信息。

实现者可自行决定模块拆分、ZIP 解析库、任务进度 UI 细节、缓存查询性能优化和内存批次大小；所有选择必须维持以上行为，避免浏览器同时堆积多年的分钟数组。
