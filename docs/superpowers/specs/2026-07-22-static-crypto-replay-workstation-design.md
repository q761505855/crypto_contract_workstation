# 纯前端加密货币合约回放工作站设计

## 1. 设计状态

- 日期：2026-07-22
- 状态：已批准
- 详细产品需求：[`项目需求-v2.md`](../../../项目需求-v2.md)
- 历史需求：[`项目需求.md`](../../../项目需求.md)

本文记录需求讨论中已经确认的架构决定。详细功能、数据模型、测试和验收要求以 `项目需求-v2.md` 为准。

## 2. 目标

构建一个部署在 GitHub Pages 上的纯前端个人工作站，提供：

- 币安 USDT 本位永续合约历史数据；
- 多周期 K 线查看；
- KLineChart Pro 指标和画线功能；
- 历史逐根回放；
- 单交易对、单净仓位的手动模拟交易；
- 开仓、加仓、减仓、止盈、止损和近似强平；
- 只读实时行情；
- 本地持久化和可选 GitHub 私有仓库同步。

## 3. 已选方案

采用“直接集成 KLineChart Pro，在外层扩展交易工作站功能”的方案。

选择原因：

- 复用交易对、周期、指标、画线、时区、设置、截图和全屏界面；
- 避免重复开发图表基础设施；
- 自定义 Datafeed 可以同时支持本地历史数据和币安实时行情；
- Chart Adapter 可以隔离较旧的 Pro 依赖版本；
- 只有公开扩展能力不足时才需要维护轻量分支。

未选择的方案：

- 直接 Fork 并深度修改 Pro：自由度高，但维护和耦合成本更高；
- 只用 KLineCharts 核心重做 Pro 界面：重复工作过多，不符合首版目标。

## 4. 架构

```text
GitHub Pages
├── React App Shell
├── Chart Adapter
│   └── KLineChart Pro
├── Binance Datafeed
│   ├── Public REST
│   └── Public WebSocket
├── Replay Engine
├── Simulation Engine
├── IndexedDB / localStorage
└── GitHub Sync Adapter
    └── Private data repository
```

模块边界：

- KLineChart Pro 负责图表、指标和画线；
- Binance Datafeed 负责所有交易所公开数据；
- Replay Engine 负责模拟时间和可见数据；
- Simulation Engine 负责全部账户与交易计算；
- IndexedDB 是运行时主存储；
- GitHub 私有仓库是手动触发的备份和跨设备同步层。

## 5. 关键产品决定

### 5.1 模式

- 历史模拟模式支持交易；
- 实时行情模式只读；
- 两种模式都可以读取历史数据。

### 5.2 市场和周期

- 动态读取所有正在交易的币安 USDT 永续合约；
- 支持币安常用完整周期集合；
- 一个图表一次只显示一个周期，不做多周期联动。

### 5.3 模拟交易

- 一个会话只交易一个交易对；
- 一个会话只保留一个净仓位；
- 单向持仓、逐仓保证金；
- 市价开仓、加仓、减仓和全平；
- 止盈、止损和近似强平；
- 不支持限价单、部分成交、订单簿或逐笔回放。

### 5.4 K 线级撮合

- 市价操作使用当前可见 K 线收盘价并加滑点；
- 止盈、止损和强平从下一根 K 线开始判断；
- 使用最高价和最低价判断触发；
- 不推测 K 线内部路径；
- 同一根 K 线的保守优先级为强平、止损、止盈。
- 单步、倍速和跳转都必须顺序处理每根 K 线，不得跳过中间触发条件。

### 5.5 强平

- 强平仅为历史训练近似值；
- 使用标记价格 K 线；
- 维持保证金率和强平费用可配置；
- 页面必须持续显示非交易所精确结果的提示。

### 5.6 存储和同步

- IndexedDB 保存行情、会话和交易；
- localStorage 保存界面偏好；
- 支持 JSON 导入导出；
- GitHub 同步使用独立私人仓库；
- 使用只允许指定仓库 Contents 读写的 Fine-grained Token；
- Token 只保存在页面内存；
- 历史行情按月压缩分片；
- 同步由用户手动触发并串行执行；
- 使用 SHA 进行乐观并发控制。

## 6. 错误处理原则

- 本地缓存可用时，币安请求失败不得阻止历史查看；
- 数据缺口未补齐时禁止跨越缺口回放；
- 标记价格缺失时停止强平判断；
- WebSocket 断线必须显示状态并通过 REST 补齐；
- GitHub 同步失败不得破坏本地数据；
- Token 不得进入日志、持久化存储或导出文件；
- IndexedDB 迁移失败时保留原数据并允许导出。

## 7. 测试策略

测试分为：

- 单元测试：数据、回放、交易、强平、存储和冲突处理；
- 集成测试：Datafeed、IndexedDB、Chart Adapter、GitHub API；
- 端到端测试：历史下载、回放、交易、恢复、实时行情和云同步；
- 部署测试：GitHub Pages 子路径、静态资源和无后端依赖。

持续集成使用模拟外部接口，不依赖币安或 GitHub 的实时可用性。

## 8. 实施顺序

1. 静态项目、KLineChart Pro 和 GitHub Pages；
2. Binance Datafeed 和 IndexedDB 历史数据；
3. Replay Engine；
4. Simulation Engine 和图表交易覆盖物；
5. 只读实时行情；
6. 导入导出和 GitHub 私有仓库同步。

实施计划必须在用户审核本设计和详细需求后另行编写。
